### 演示 3：智能挂号 HITL（15 分）

输入 `明天有哪些号源` → 出现排班表格

点第一行「挂号」按钮 → 预览卡片（患者ID、排班、余号）

点「确认挂号」→ 凭证卡片（绿色大字 YYH... 凭证号）

话术：
> "整个流程走 LangGraph 条件边：book_preview 节点只读号源生成预览，用户说'确认'后进入 book_execute 节点才真正 POST 挂号。100% 先预览后确认。预览和执行两处都校验号源——预览时查实时余号，执行时若被抢则返回明确错误引导改约。"

### 演示 4：限约机制（主动讲解，加分项）

再挂一次同一科室同一天，会看到：

> 挂号失败：您今天在该科室已有预约，请勿重复挂号。

话术（这段要背）：
> "这不是 bug，是需求里明确要求的『同患者同日同科室限约 1 次』。实现方式是数据库唯一约束兜底（uk_clinic_patient_dept_date_active），而不是 SELECT 预检——因为 SELECT 在并发下有 TOCTOU 漏洞（先查后写之间被人抢插）。取消时把 active_key 置 NULL，MySQL 唯一索引允许多个 NULL，就释放了限约。"

### 演示 5：取消预约 HITL

输入 `查我的预约` → 出现预约表格

点「取消」→ 取消预览卡片 → 点「确认取消」→ "已取消预约 YYH...，号源已返还"

### 演示 6：身份边界

打开 Swagger 展示 GET /clinic/bind/me 返回：

{"code":200,"data":{"bound":true,"patientId":1001,"bindType":"SELF"}}

话术：
> "AI 智能挂号时，patientId 不从聊天文本或前端参数取，而是通过这个接口从若依登录态查绑定。所以『帮别人挂号』在聊天里是不可能做到的。"

## 四、7 个必答问题（题面第八节）

Q1: "咳嗽发烧是不是肺炎，吃阿莫西林行吗" 怎么处理？

> 护栏第一层命中"是不是.*炎"（诊断）+ "阿莫西林"（药物），直接返回 REFUSAL_ANSWER，不进路由。

Q2: 号源防超卖有哪两种方案？

> 条件 UPDATE + 悲观锁（SELECT FOR UPDATE）。本项目用条件 UPDATE：
> UPDATE clinic_schedule SET remaining_quota = remaining_quota - 1 WHERE schedule_id = ? AND status = 'OPEN' AND remaining_quota > 0
> 返回 0 行说明号源已抢光。CAS 语义，不阻塞其他事务，天然幂等。悲观锁会阻塞，吞吐量低。

Q3: 预览和执行两处都校验号源，为什么？

> 预览到执行之间有时间窗口，号源可能被别人抢走。执行时第 2 次条件 UPDATE 返回 0 行 → 抛异常 → 事务回滚 → 明确告知用户"号源刚被抢完，请重新选择"。

Q4: "推荐科室"和"诊断"的边界？

> 推荐只依据带引用的科室介绍检索结果。回答里必带"OCMS3-13 · 内科科室介绍"这种引用标签。引用文字写"科室服务范围是...，不是诊断结论"。LLM 只能在检索到的资料里组织答案。

Q5: AI 和人工走同一个 Service 吗？

> 是。AI 调 /clinic/appointment/book → ClinicAppointmentController.book() → ClinicAppointmentServiceImpl.book()。人工走"预约管理 → 挂号"也是同一个 Service。业务规则单点，不重复实现。

Q6: 患者身份从哪来？

> 后端 SecurityUtils.getUserId() → 查 clinic_user_patient_bind → 得 patientId。前端不传 patientId，AI 也不传（聊天文本里即使说"给张三挂号"也无效）。

Q7: 拒答记录为什么落日志？

> 合规审计需要——万一有投诉，能追溯"AI 什么时候、对谁、拒绝回答了什么"。本项目落 clinic_operation_log 表，字段含 business_type / action / result / detail。

## 六、应急方案

| 现场故障 | 应急动作 |
|---|---|
| Agent 崩了 | .\scripts\start-all.ps1 重启 |
| 前端白屏 | F12 看 Console；Ctrl+Shift+R 强刷 |
| 数据库连不上 | 检查 MySQL 服务 + .mysqlpass |
| 网络断了 | 全部服务本地，离线可用（LLM 默认关闭） |
| 忘记密码 | .mysqlpass 文件里有 |

备注：LLM_ENABLED=false 时走"检索 + 模板"降级，完全离线可用，不怕断网。
