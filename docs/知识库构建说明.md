# 知识库构建说明

## 一、知识来源

- 18 篇 materials/stage3-knowledge/*.md
- 每篇有 YAML frontmatter：doc_id / title / department / source
- 8 篇权威原文（materials/dify-knowledge-import/*.md）为逐字副本，来源校验见 materials/knowledge-provenance.json
- 其余为阶段三适配稿（补身份绑定、确认办理等阶段三专属内容）

## 二、分块策略（scripts/build_kb.py）

### 1. Frontmatter 解析

用简单实现（不依赖 pyyaml）：

- 正则匹配开头的 --- ... ---
- 逐行 split(":", 1) 取 key/value

### 2. 按二级标题分块

- 用正则 ^##\s+ 切分
- 第一段（无 ## 的前言）归为"概述"
- 其余每段：第一行是 heading，其余是 content

**为什么按 ## 而不按固定字数**：

- 门诊知识文档的 ## 是语义完整的业务单元（如"第一次使用青枫门诊如何挂号"）
- 固定字数切分会破坏语义
- 18 篇文档共切分 **67 个 chunk**

### 3. 分块 metadata

每个 chunk 包含：

- chunk_id（如 OCMS3-01#00）
- doc_id / title / department
- heading / content
- source_file（原始文件名）

## 三、检索：BM25 + 科室过滤

### 索引

rank_bm25.BM25Okapi + jieba 分词。

### 科室过滤

当指定 department 时，把非目标科室且非"公共"的 chunk 分数置为 -inf。

**关键设计**：公共科室始终保留——包含"就诊流程""挂号规则"等跨科室通用知识。

## 六、升级路径

**当前**：BM25 单词检索。

**可升级**：

1. BM25 + 向量混合检索：加 sentence-transformers 或调用 embedding API
2. Rerank：用 bge-reranker 或 Cohere Rerank
3. 分块自适应：长 chunk 二次切分，按 heading 层级加权

**本次不做的原因**：作业时长为 4 天，BM25 已能覆盖 15/15 知识问答用例，优先把预算投到 HITL 与护栏。
