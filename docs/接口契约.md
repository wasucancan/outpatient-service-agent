# Java ↔ Python 接口契约

## 一、认证

所有涉及本人数据的请求必须携带若依 JWT：`Authorization: Bearer <token>`

- 若依前端：`getToken()` 从 store/cookie 取出
- Python Agent：`chat.js` 从请求头取，透传到 `clinic_client.py`

服务级 token：Agent 在只需读公共号源时，会用 admin/admin123 自己登录拿服务 token。

## 二、AI 调用的若依接口

### R1. 绑定查询（关键）

GET /clinic/bind/me

响应：

{"code":200,"data":{"bound":true,"bindId":1,"patientId":1001,"bindType":"SELF","userId":1}}

未绑定：data.bound = false。

**为什么关键**：AI 挂号 / 取消 / 查本人预约前必须调这个接口拿 patientId，不信前端传参。

### R2. 排班列表

GET /clinic/schedule/list?status=OPEN&pageNum=1&pageSize=50

响应 rows[]：scheduleId / departmentId / doctorId / visitDate / period / startTime / endTime / totalQuota / remainingQuota / status

### R3. 排班详情

GET /clinic/schedule/{scheduleId}

### W1. 挂号（写操作）

POST /clinic/appointment/book
Content-Type: application/json

{"scheduleId": 5001, "source": "AI"}

**不传 patientId**，后端从登录态绑定的患者档案取。

成功 data：appointmentId / appointmentNo / visitDate / period / departmentId / doctorId / status

失败响应（HTTP 200，业务 code ≠ 200）：

{"code": 500, "msg": "您今天在该科室已有预约，请勿重复挂号"}

可能的失败：

| msg | 场景 |
|---|---|
| 号源已满，请选择其他时段 | 预览到确认之间被抢 |
| 您今天在该科室已有预约 | 唯一约束拦截 |
| 排班已关闭 | status ≠ OPEN |
| 该时段已开始 | start_at < now |

### W2. 取消预约（写操作）

POST /clinic/appointment/cancel/{appointmentId}
Content-Type: application/json

{"reason": "AI 助手代取消"}

失败：{"code": 500, "msg": "就诊开始前 2 小时内不可取消，请到院处理"}

### R4. 本人预约列表

GET /clinic/appointment/list?patientId=1001&status=BOOKED&pageNum=1&pageSize=20

### R5. 预约详情

GET /clinic/appointment/{appointmentId}

## 三、错误结构

{"code": 200 | 500 | 401, "msg": "...", "data": {...}}

## 四、超时 / 重试

| 接口 | 超时 | 重试 |
|---|---|---|
| /clinic/bind/me | 15s | 不重试 |
| /clinic/schedule/* | 15s | 不重试 |
| /clinic/appointment/book | 15s | 不重试 |
| /clinic/appointment/cancel/* | 15s | 不重试 |

写操作绝不重试——依赖条件 UPDATE 的幂等性。

## 五、幂等性

| 操作 | 幂等方案 |
|---|---|
| 挂号 | 唯一约束 uk_clinic_patient_dept_date_active 兜底 |
| 取消 | WHERE status = 'BOOKED'，第二次影响 0 行 |
| 扣号 | WHERE remaining_quota > 0 |
| 返号 | WHERE remaining_quota < total_quota |
